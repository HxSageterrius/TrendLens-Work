# TrendLens — Data Provenance

**Read this before citing any number from the dashboard.** This document states exactly what is
real, what is simulated, and what is *not* claimed.

## Fashion Catalog (`data/fashion_trends/`)

| Aspect | Status |
|---|---|
| Images | 79 JPGs: 39 curated `DF2_*` garment photos (Unsplash stock photography) + 2 sneakers + 2 bags + 36 legacy `FSH_*` items. **Not** the official DeepFashion2 dataset. |
| Annotations | 43 DeepFashion2-*schema* JSONs with hand-authored bounding boxes, `pair_id` shop/user pairs, and category labels. Annotation attributes (`scale`, `occlusion`, `zoom_in`, `viewpoint`) are fixed placeholder values. |
| Engagement metadata | `likes` / `comments` / timestamps in `fashion_posts_metadata.csv` are **synthetic** (generated by the builder script, not scraped). |
| Rebuild script | `scripts/build_deepfashion2_dataset.py` (downloads images from hardcoded Unsplash URLs; falls back to PIL-drawn placeholders offline). |
| Trend series | `insta_fashion_trends.csv` — 6 styles × ~101 weekly rows, **simulated** by `src/preprocessing/trendverse_data_builder.py` with `RANDOM_SEED=42` (deterministic). |
| Committed vs generated | The committed CSVs are the source of truth for the dashboard. The seeded builder's output may differ from the committed files; rebuilding is not required and will overwrite artifacts. |

## Automotive POC (`data/automotive/`)

| Aspect | Status |
|---|---|
| Images | 45 real JPEGs from the **Stanford Cars** dataset (CVPR 2011), selected by a hardcoded smoke-test manifest in `src/preprocessing/automotive_adapter.py`. |
| Annotations | `cars_annos.mat` / `cars_train_annos.mat` (official label files, gitignored due to size) + derived catalog CSV with body types inferred by keyword heuristics. |
| License | See `data/automotive/ATTRIBUTION.md` and `LICENSE.txt`. |

## Embeddings, Clusters, Forecasts

- `data/embeddings/*.npy` — generated output (not committed); rebuilt automatically on first API
  startup or by `src/pipeline_runner.py`.
- `data/forecasts/*.json` — computed from the catalog and simulated series at pipeline runtime.
  Forecast metrics (MAE/RMSE/MAPE) are **in-sample** measures of fit on the simulated series —
  they describe model fit, not real-world forecast accuracy.
- DBSCAN `eps` is calibrated per catalogue (fashion 0.30, automotive 0.2); on the current catalogs
  DBSCAN reports a single density mass plus outliers — it is a density check, not a second taxonomy.

## Explicitly NOT Claimed

- ❌ No official DeepFashion2 data or benchmark numbers.
- ❌ No measured Top-K retrieval accuracy is committed — the dashboard reports similarity scores,
  not retrieval-accuracy benchmarks.
- ❌ No real social-media engagement or search-volume data.
- ❌ No automotive trend forecasting (no temporal popularity data; see
  `data/automotive/forecasts/automotive_forecast_status.json` for what data would enable it).

## Planned / Not Implemented

CLIP embeddings, PostgreSQL persistence, WordPress/PHP reporting, full Stanford Cars run, and the
CompCars dataset are roadmap items, not part of the current codebase.
